  without blocking anything.

## Open questions

- **Pulumi state backend**: currently Pulumi Cloud for the proxy's state.
  Luís floats testing the team's own GCS bucket instead — never done it
  before, expects **less visibility** into some things as the cost, and isn't
  sure the project is big enough to need what Pulumi Cloud gives for free.
  Genuinely undecided; feeds directly into the open "Pulumi state backend"
  item on [[2026-08-21 Deploy Airtable Proxy privately behind VPN]].
- **GCP account-tier risk, newly surfaced**: on the current (first paid) plan,
  there's no per-user project isolation — any user added to the account can
  see every project, including ones that aren't theirs. Luís frames this as a
  real risk (one person's mistake could take down the whole shared infra), and
  believes only the **Enterprise** tier (not even Business) fixes it. Not
  resolved — just flagged as something to keep in mind before more people get
  access.

## Facts stated

- Matheus: local integration is done and working — LiveScript and the proxy
  run together locally using the URL-suffix app-identification scheme, and
  Grafana confirms data is flowing end-to-end.
- Matheus: the metrics being captured are exactly what was scoped in the
  Jira/design doc — whether a request has a filter, which request/operation it
  is, and the response size in bytes. Nothing extra was added.
- Matheus: the one thing he could **not** get was identifying which LiveScript
  **Handler** triggered a given proxy call — that would require a change on
  LiveScript's own side, which he didn't make. Confirms this is still open
  work (already tracked as "normalize `app.route`" on [[Airtable Proxy]]).
- **Neither of them had actually looked at a built dashboard before this
  call.** Matheus assumed Luís wanted to see live/raw data, not a
  dashboard — he hadn't built one and said his Grafana knowledge was "bem
  simples." Luís clarifies what he actually wants: a **management-level
  view** of the captured data, for decision-making, distinct from looking at
  individual data points.
- On the call, they find Grafana's pre-existing default "antipatterns" panel
  (Explore → antipatterns, not something Matheus built) already firing on
  Matheus's own last-6-hours of local testing: **2× full table scan** and
  **2× select without field projection**. First time this default dashboard
  was actually looked at.
- Matheus didn't open a PR for this branch of work — he pushed/merged
  directly, reasoning it doesn't matter yet since nothing is in production.
  Luís treats this as fine, not a process violation — "a gente vai achando
  esse jeito de trabalhar aos poucos" — and reiterates that when he does need
  a PR, Matheus should default to opening one, since it's easier for him to
  review that way.
- Matheus, on where he's at with the agentic-flow track: he now feels **more
  confidence and firmer footing**, having concrete concepts to reason with
  instead of vague notions — a shift he attributes directly to the last few
  conversations.
- Luís is "bem bem bem bem otimista" about the agentic flow, and expects Carol
  to get excited once she understands what it can actually do.
