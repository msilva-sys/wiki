## Decisions

- **Onboarding runs both tracks in parallel**, proxy first. See
  [[2026-08-10 Onboarding runs proxy and agent flow in parallel]].
- **The proxy terminates Airtable credentials.** Apps authenticate with their own
  internal key; the Airtable PAT lives inside the proxy and is never exposed.
  (Confirms what [[Airtable Proxy]] already recorded from the design doc.)
- **Migration is a base-URL swap, not a DNS cutover.** Apps repoint at a proxy
  host — `airtable.livemode.space` was named as the illustrative form — and the
  proxy passes through transparently. Expected to be near-zero effort for app
  owners: *"Só de mudar, ele tem que ser meio que um funcionamento transparente,
  ele só tem que passar para a frente."*
- **Two initiatives were merged** into one: the proxy project and LiveScript
  stabilization. See [[LiveScript]].
- **The Airtable-side agent work starts scoped to a single project.** The
  monitoring/watch agent is the suggested first build, pointed at one project
  (LiveScript or "Orca") rather than at everything.

## Facts stated

Gabrielle Ferreira, unless noted. These are **spoken claims** — weaker evidence
than the repo or the design doc. Where they conflict, the code wins and the
conflict gets recorded.

- Livemode started as a single product, then built satellite applications to
  enrich the experience. **[[LiveScript]] is by far the heaviest Airtable user.**
- **The triggering incident was the World Cup**: a day with many simultaneous
  users on an application that requires real-time editing and real-time feedback.
  Airtable's API limits could not absorb it.
- To cope, the team added **locks** (*travas*) that are still in place and are
  product debt, not design intent — detailed in [[LiveScript]].
- A **second application also uses Airtable and is badly implemented** — refetching
  and over-loading without need. Gabrielle was explicit that this one is not a
  business-need problem: *"o problema dele não é a necessidade de negócio, ele
  está mal implementado."* It was built fast, partly by a non-technical
  contributor, on top of something that already existed.
- **Finding bad usage by hand doesn't scale** — the stated rationale for building
  detection into the proxy instead: *"se eu tiver que ficar procurando essas más
  práticas aqui, é muito mais trabalhoso do que eu criar um cara mega inteligente
  aqui que ele identifica e alerta."*
- **The proxy is expected to handle 429s with retry/backoff on the apps' behalf**,
  so individual applications don't implement their own retry logic.
- **A Grafana proof-of-concept already existed and was working** at the time of
  this meeting.
- Observability is *"importantíssima"* — the central pillar, not a side feature.
- **Phase 2 of the merged initiative**: data that doesn't need to be in Airtable
  moves to a database belonging to LiveScript alone.
- A **prior agent attempt failed on adoption, not capability** — see
  [[Agent Flow]].
